An IDE for C# and .NET, written in C#.

Inspired by Rider: an editor of its own over Roslyn, a debugger and a profiler of its own, unit tests, Git, NuGet and a terminal. And your coding agent can use all of it too: debugging, profiling and testing in the same IDE you do.

Download Source on GitHub

For Windows and macOS, with builds for Linux.

A whole IDE, in one language

Everything in Passenger is .NET, from the window to the debugger, built on the libraries a C# IDE needs: Roslyn, MSBuild, ICorDebug, EventPipe and VSTest.

The editor

A text control of its own over an immutable rope: multiple carets, code folding, Extend Selection, live and postfix templates, and Rider's Visual Studio keymaps with their chords. It keeps up with every keystroke in a 50,000-line file.

C# from Roslyn

Colours, diagnostics, completion, hovers and signature help, quick fixes and refactorings, rename, Go to Declaration and Implementation, Find Usages, call and type hierarchies, and decompiled library sources.

Build and run

A Solution view of your projects, builds with their errors in Problems, run configurations from your launch profiles, and Hot Reload under dotnet watch.

Unit tests

xUnit, NUnit and MSTest found and run through VSTest, run marks in the gutter, results by project, class and method, failures rerun, and any test debugged.

NuGet

Search nuget.org, then install, update and remove packages for each project, with central package management.

Terminal

A terminal emulator of its own with a shell per tab, where vim, less and htop run full-screen.

A debugger of its own

Over the runtime's ICorDebug: breakpoints with conditions, hit counts and log messages, stepping through async code, Run to Cursor and Set Next Statement, the call stack and threads, variables you can open and set, watches and evaluation, and the values each line used drawn after it. Attach to a .NET program already running, on a Mac too with nothing to set up.

A profiler too

Sampling over EventPipe, from a program's first instruction: its call tree, hot spots, flame graph, allocations and garbage collections, narrowed to any stretch of the timeline. A memory snapshot counts a running program's heap by type.

Git

The Commit window with its changes, the log with its branch graph, side-by-side diffs, blame, change bars in the gutter that roll a change back, branches, stashes, push, pull and fetch.

Find anything

Search Everywhere, Go to File, Go to Symbol and Find Action, Find and Replace in Files with a preview, Recent Files, bookmarks and File Structure.

Your coding agent, using the IDE as you do

Connect a coding agent such as Claude Code to Passenger and it works through the IDE, not just your files. It finds where things are declared and used, reads the compiler's warnings, and renames and fixes code as the IDE does. It builds, runs and tests. It sets breakpoints, steps through the program, reads and changes its variables, and profiles a run to find what is slow. It commits, adds packages, types into the terminal, and takes a screenshot to see what you see.

Connect it to the window you have open and watch it work: its breakpoints and stops show in your editor, its runs in your Run window. Or give it a Passenger of its own with no window, for work it does alone. A window lets agents in only once you turn on Settings › MCP Server › Enable MCP Server, through a connection only you can reach, and asks you the first time an agent wants to change anything.

Tell your agent to start Passenger with --mcp-attach, and it joins the window you have open. Passenger is /Applications/Passenger.app/Contents/MacOS/Passenger on a Mac and %LOCALAPPDATA%\PassengerIDE\current\Passenger.exe on Windows. For a Passenger of the agent's own, with no window, use --mcp and the folder or solution instead.

Claude Code 
claude mcp add passenger -- \
    /Applications/Passenger.app/Contents/MacOS/Passenger \
    --mcp-attach
Claude Desktop

In Settings › Developer, choose Edit Config, add Passenger, then restart Claude:

{
  "mcpServers": {
    "passenger": {
      "command": "/Applications/Passenger.app/Contents/MacOS/Passenger",
      "args": ["--mcp-attach"]
    }
  }
}

On Windows the command is Passenger.exe's full path, each \ written \\.

Codex CLI 
codex mcp add passenger -- \
    /Applications/Passenger.app/Contents/MacOS/Passenger \
    --mcp-attach

Or in ~/.codex/config.toml:

[mcp_servers.passenger]
command = "/Applications/Passenger.app/Contents/MacOS/Passenger"
args = ["--mcp-attach"]
Codex desktop app

In Settings › MCP servers, choose Add server, name it passenger, choose STDIO, give Passenger's path as the command and --mcp-attach as its argument, then save and choose Restart. The app and the Codex CLI share their settings, so adding it in one adds it to both.

Passenger connects through MCP, the standard most coding agents use to reach their tools, so any other agent that can add an MCP server connects the same way.

How to install on Linux

Passenger needs a .NET SDK, version 10 or later: it builds and runs your projects with it, and Roslyn's language server runs on it. Version control needs Git. Every release, with its notes and checksums, is on GitHub.
