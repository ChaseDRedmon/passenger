Passenger 0.2.0 runs an app made of several services as one: a Docker Compose file's services, a Dockerfile's, or an Aspire app's from its AppHost, every .NET service under the debugger, Hot Reload and the profiler wherever it runs. It shows a web app's routes from its code and the requests it serves as they come, with the SQL each one ran; it works EF Core's migrations against the database your run uses; and it knows your app's configuration from the code that reads it. Your coding agent can do all of it through Passenger too.

It is still free and open source under MIT, and still includes what usually takes a paid IDE or add-on: this time debugging and profiling inside containers, a live view of requests and their queries, and a Migrations window that fixes what would stop `dotnet ef` before it runs. Everything this release closed is in its [0.2.0 milestone](https://github.com/Zaneris/passenger/milestone/3).

## Containers and Docker Compose

A container is one more place a .NET service runs, with nothing to set up beyond a Dockerfile or a compose file. Passenger works through your own `docker` command and whatever its context reaches: Docker Desktop, Colima, OrbStack, Rancher Desktop, Podman or a remote engine ([#242](https://github.com/Zaneris/passenger/issues/242)).

- **Containers are run configurations.** Each compose file (with its override), each project with a Dockerfile, each project that asks the .NET SDK for its image, and each Docker Compose project (`.dcproj`) is found as the solution opens, and `Docker`, `DockerCompose` and `SdkContainer` launch profiles run rather than being greyed. Run > Edit Configurations has a page for each kind: its files, env files and profiles, and Run, Debug or Don't start for each .NET service ([#343](https://github.com/Zaneris/passenger/issues/343)).
- **Fast, or as deployed.** By default Passenger builds the .NET services itself and runs each from its build, mounted into its image's runtime stage, so a code change needs no image rebuild and Rerun restarts only the services whose build changed, on the same ports. Choose Build images, as deployed to run the images as Compose builds them.
- **Debug every service at once.** Debug holds each .NET service at its start, attaches Passenger's own debugger inside its container and lets it go, so a breakpoint in `Main` stops; each service gets a Debug tab with its container's log as its console. Run with Hot Reload applies your edits to every service as they run, and an edit Hot Reload can't apply rebuilds and restarts only the service that holds it ([#344](https://github.com/Zaneris/passenger/issues/344)).
- **One service at a time.** From a service's row in the Containers window, or the run icon beside it in the compose file: debug it, attach to it, run it without the debugger, restart or profile it while the others run on. A service marked Don't start can be started later in the same run.
- **Attach to Process reaches into containers,** listing the .NET programs in every running container, those Passenger didn't start too, and debugging the one you choose there.
- **Profile inside containers.** CPU traces and memory snapshots are taken in the container and shown as any others are: hot spots at their lines, snapshots compared. Profile on a container configuration records a service from its first instruction, and Attach Profiler one already running ([#345](https://github.com/Zaneris/passenger/issues/345)).
- **The Containers window** (Tools): Compose projects with their services, then every other container (Testcontainers' apart), images, volumes and networks, each with its state, health and ports as links. Start, Stop, Restart, Pause, Remove, Pull, Scale, Prune and Inspect; a container's Log with Find, Stats, Files (opened read-only) and Details; Open Shell in a Terminal tab. The status bar says when there's no engine or it isn't running, and starts Docker Desktop where it's installed ([#342](https://github.com/Zaneris/passenger/issues/342)).
- **Logs and traces from a compose app.** Turn on Collect logs and traces with Aspire's dashboard in a container configuration, and its .NET services' structured logs and traces show in the Containers window's Telemetry tab, a request's spans put together across services, as an Aspire app's do. It is off at first, since the dashboard's image is pulled the first time ([#405](https://github.com/Zaneris/passenger/issues/405)).
- **Code help in Dockerfiles and compose files.** Language servers for Dockerfiles and YAML, compose files checked against the Compose specification, BuildKit's own checks on a Dockerfile as it opens and saves, and Compose's own reading of a compose file as you type: its errors on their lines, each `${VAR}` followed by what it comes to (a secret's value as dots), Go to Declaration, Rename and completion of the file's services, volumes, networks, secrets and configs, and fixes for a name nothing declares. A .NET service whose code reads a connection string the compose file never gives it is warned of in both files, with a fix that sets it ([#346](https://github.com/Zaneris/passenger/issues/346), [#411](https://github.com/Zaneris/passenger/issues/411)). Settings has a Docker page for completing image tags from Docker Hub and for BuildKit's checks, which read base images' details from their registry; both are on at first.
- **Add > Docker Support** writes a Dockerfile and `.dockerignore` for a project, or sets the SDK's container properties instead, and **Add > Docker Compose** writes a `compose.yaml` for the projects you choose, with the backing services their packages call for (Postgres, SQL Server, MongoDB, Redis, RabbitMQ), each with a healthcheck and its connection string. Undo takes either back in one step.
- **Nothing left behind, nothing of yours taken.** Stop, closing the folder and quitting take down what a run started, and the next start removes what a crash left. Your own containers of the same Compose project are never removed, and Passenger asks before replacing them. A service that serves HTTPS gets your development certificate, after asking whether to create and trust one when it's missing, and in Development the project's user secrets, both mounted read-only.

## Aspire

Passenger is the IDE an Aspire app runs under: an AppHost, a project or a single-file `apphost.cs`, is a run configuration, and Aspire's orchestrator asks Passenger to start each project resource, so every .NET service runs under Passenger ([#243](https://github.com/Zaneris/passenger/issues/243)).

- **Run, Debug, Run with Hot Reload and Profile the whole app.** Debug debugs every service at once, a Debug tab each, or those you mark Debug in Edit Configurations; Hot Reload reaches each; Profile holds the service you choose at its start and records it from its first instruction. A service restarted is debugged again, and Rerun builds and restarts only what changed, the AppHost too when its own code did.
- **The Aspire window** has the Containers window's layout: the AppHost's resources with their state, health and addresses as links; Details (environment, URLs, relationships, health reports and volumes, with secrets masked); the resources' consoles merged into one Log with Find; Telemetry, the structured logs and traces the services send; and the AppHost's own log. A resource's own commands run from its row, and the AppHost's prompts come up as Passenger's dialogs. An AppHost started outside Passenger shows there too, through the `aspire` command.
- **Its containers go with it.** The containers an AppHost makes are listed under it in the Containers window and removed with the run, the folder or the IDE however it ends, with their network. A container you made Persistent stays yours. When Aspire runs them on Podman beside Docker, Passenger follows them there.
- **Code help across the AppHost.** Resource names complete, and `AddProject` goes to its project. In a service, Go to Declaration on a connection string's or a discovered service's name goes to the AppHost line that declares it, and Rename renames a resource there and in every service that reads it. A service that reads a connection string its AppHost never gives it is marked with a fix that adds the `WithReference`; a name no resource has, with the nearest one as its fix; and a parameter with no value, with a fix that sets it in the AppHost's user secrets or appsettings.json ([#406](https://github.com/Zaneris/passenger/issues/406)).
- **Add > Aspire Orchestration** adds an AppHost and ServiceDefaults to a solution, with the backing services its projects use, each referenced by the services that read it. Undo takes it back in one step.
- **HTTPS ready.** Before an AppHost that serves HTTPS starts, your development certificate is checked, and when it's missing or untrusted Passenger asks once whether to create and trust it or run over HTTP.

## Web apps and their data

- **Endpoints, from your files and your code.** The Endpoints window (Tools) lists the requests in the folder's `.http` and `.rest` files: Test sends one and checks its answer against the file's `# @expect` lines, and Interactive Test changes it and sends it again without touching the file. Nothing sends your environment variables, or a file outside the folder, to a host without asking first. Each web project's routes are listed too, read from its code with no build or running app: minimal APIs, controllers, Razor Pages, Blazor pages, SignalR hubs and gRPC services. A route's line has an icon that sends its request to the running app, writing it into the project's `.http` file the first time, and Go to Declaration and Find Usages go between a request and its route ([#417](https://github.com/Zaneris/passenger/issues/417)).
- **Live requests and their SQL.** The Requests window shows the requests a running web app serves and the database commands each one ran, with their times and rows, for Run, Debug and Profile and for the services of a container run or an AppHost, with no change to the app: Passenger reads ASP.NET Core's and EF Core's own events, and only while you look. A command run again and again in one request (an N+1) or a slow one is marked, a parameter shows as the app logs it with a secret's value as dots, a request opens at its handler or at the exception that ended it, and a command's SQL opens in a tab ([#418](https://github.com/Zaneris/passenger/issues/418)).
- **EF Core migrations.** The Migrations window (Tools) lists each DbContext's migrations and whether the database has them, with Add Migration, Remove Last, Update Database to the latest or a chosen one, Script and Bundle. Before a command runs it finds what would stop `dotnet ef`, and offers the fix in place: the tool missing or of another version (added as a local tool at your EF Core's version), the Design package missing, a database provider behind your EF Core's version, a context the tools can't make. While a compose run or an AppHost is up, it works on the database that run uses. After a build, model changes no migration covers are a warning in Problems, with Add Migration as its fix ([#419](https://github.com/Zaneris/passenger/issues/419)).
- **A query's SQL in the debugger.** When the program stops holding an EF Core query, Variables and the hover card show a SQL row; opened, it shows the SQL the query would run, which opens whole in a tab ([#420](https://github.com/Zaneris/passenger/issues/420)).
- **Configuration known from your code.** `appsettings*.json` and user secrets complete the keys your code reads and the options classes it binds, with their types; Go to Declaration goes from a key to the code and back; and the hover card on a read says which file gives the key its value. A key read with no default that nothing gives is warned of where it's read, with a fix that adds it to appsettings.json, or to user secrets when its name says it's a secret. Manage User Secrets on a project sets them up and opens its `secrets.json` ([#421](https://github.com/Zaneris/passenger/issues/421)).

## Debugging and profiling

- **Several programs at once.** Debug and Attach start a session beside those running, each in a tab of its own in the Debug window, with your breakpoints sent to all. A stop in any brings its tab forward; Stop ends the chosen one and Run > Stop All the rest. Two Avalonia or WPF apps each keep their own Live Visual Tree ([#341](https://github.com/Zaneris/passenger/issues/341)).
- **The hover card opens objects.** Resting the pointer on an object, a struct or a collection while paused shows its row, which opens into its members as Variables does ([#340](https://github.com/Zaneris/passenger/issues/340)). Variables now opens and closes a row with Right and Left.
- **Continue and the steps answer at once,** however slow the values the stop is still reading ([#315](https://github.com/Zaneris/passenger/issues/315)).
- **Hot Reload** takes edits to a module the program loads later, such as a plugin, and when it applies nothing it says why, such as a file saved since the build the program runs.
- **WPF's XAML Preview** draws a window as itself, so bindings to an ancestor Window or Page and `Window.GetWindow` work as they do in the app ([#350](https://github.com/Zaneris/passenger/issues/350)), and runs your code in design mode, as Visual Studio's designer does, so code that checks `DesignerProperties.GetIsInDesignMode` skips what only the running app should do ([#351](https://github.com/Zaneris/passenger/issues/351)).
- **The profiler:** a program Profile started goes on after Get Snapshot as one you can stop, and Attach Profiler finds a program running in the terminal, and under Hot Reload the app itself rather than `dotnet watch`.
- **Fixed:** an expression in Evaluate runs once, when you ask, not again at every stop ([#283](https://github.com/Zaneris/passenger/issues/283)); a breakpoint changed while debugging starts reaches the program ([#282](https://github.com/Zaneris/passenger/issues/282)); a breakpoint another thread hits as a step ends stops the program ([#284](https://github.com/Zaneris/passenger/issues/284)); a program you attached to runs on if Passenger crashes ([#286](https://github.com/Zaneris/passenger/issues/286)); floats and doubles show as C# writes them whatever your system's language ([#353](https://github.com/Zaneris/passenger/issues/353)); and an evaluation that runs past its time no longer leaves an abort to fire later, inside a lock ([#238](https://github.com/Zaneris/passenger/issues/238)).

## Your coding agent

- **Everything above reaches agents.** `containers`, `container_logs`, `container_exec` and `container_action` work with the engine, and run an Aspire resource's commands; `run`, `debug_start`, `debug_attach`, `profile` and `stop` take a `resource` (a compose service or an Aspire resource) and answer once it's up; `workspace` lists the runs, their services and a web app's routes; `output` reads a service's log, or a web app's requests and their SQL; `telemetry` reads logs and traces; the debug tools take a `session`; `build` publishes; the Migrations window's actions run through `ide_action`; and the configuration's and migrations' fixes come through `code_actions`.
- **Fewer tools, each said once.** Eleven tools that repeated another are folded into it, and the list an agent reads at the start of every session is 46 KB, though it does far more than 0.1.0's. If you call them by name: `open_file` is `open`; `screenshot` and `type` are `app_screenshot` and `app_type` with `app` set to `ide`; `implementations` is `hierarchy`; `debug_run_to` is `debug_continue` with a path and line; `debug_set_value` is `debug_evaluate` with a `value`; `breakpoint_remove` and `nuget_remove` are `breakpoint_set` and `nuget_install` with `remove`; and `run_output`, `debug_output` and `build_output` are `output`.
- **Asked first.** On your window, an agent now asks the first time it runs code in a paused program (an evaluation, a value set, typing into its input) or sets a breakpoint ([#278](https://github.com/Zaneris/passenger/issues/278)). It is asked again once the window opens another folder ([#277](https://github.com/Zaneris/passenger/issues/277)), and it can never answer its own question through the app tools ([#276](https://github.com/Zaneris/passenger/issues/276)).
- **Never left waiting.** Every question an agent waits on closes after two minutes unanswered; the window asks for your attention (the Dock icon bounces, the taskbar button flashes, or Linux's urgency hint) and the status bar says which agent waits on what. An agent that asks for progress hears what its call is doing every 10 seconds, and Settings, MCP Server gives OpenCode's setup as well as Claude Code's and Codex's.

## The editor and the rest

- **A VS Code keymap.** Passenger keeps Rider's Visual Studio keymap as its default; coming from VS Code, choose VS Code's in Settings, Keymap. Your own shortcuts are kept for each ([#336](https://github.com/Zaneris/passenger/issues/336)).
- **Publish** (the Build menu, or a project's menu) publishes a project to a folder with a publish profile, the SDK's own `.pubxml`, so `dotnet publish -p:PublishProfile=NAME` does the same; Publish Again repeats the last ([#337](https://github.com/Zaneris/passenger/issues/337)).
- **Run configurations are edited in place.** One made from a launch profile, a compose file, a Dockerfile or a project changes directly in Edit Configurations, each change marked and kept with the folder while its source changes under it. Write to Launch Profile writes it into `launchSettings.json`, and Reset puts it back ([#230](https://github.com/Zaneris/passenger/issues/230)).
- **File > Open opens any file:** a solution, project or folder as the workspace, any other file in a tab, with or without a folder open.
- **Tables:** CSV, TSV and Excel workbooks (`.xlsx`, `.xlsm`) open as tables, and Find searches their cells.
- **Images and fonts** open as read-only previews: a PNG, JPEG, BMP, GIF, WebP or ICO at its size, a TTF or OTF in its own face ([#239](https://github.com/Zaneris/passenger/issues/239)).
- **Ten more looks,** each dark and light: Sorbet, Nocturne, Saffron, Bonbon, Ledger, Slate, Orbit, Nightjar, Moss and Phosphor, in Settings, Appearance, Theme.
- **File icons:** every file has an icon of its own in the Explorer, the tabs and every file list, in each look's colours.
- **A menu bar on the toolbar** on Windows and Linux: Settings, Appearance, Show main menu as a menu bar.
- **The keys work in every window** Passenger opens: a floating tool window, a diff, the merge window ([#90](https://github.com/Zaneris/passenger/issues/90)).
- **A button at work says so.** Run, Debug, Profile, Build, test runs, Git's push, update and commit, NuGet's changes and Apply Hot Reload Changes turn a ring round their button and say each stage in the status bar from the moment they're pressed; pressed again, they say what is under way.
- **Completion matches CamelHumps:** `SB` offers StringBuilder and `IA` IPAddress ([#380](https://github.com/Zaneris/passenger/issues/380)).
- **What's New:** after an update, Passenger shows the new version's notes once, in a tab of their own; Help, What's New shows them again.

## Faster

Passenger's code was read through for performance as a whole this release ([#414](https://github.com/Zaneris/passenger/issues/414), [#233](https://github.com/Zaneris/passenger/issues/233), [#441](https://github.com/Zaneris/passenger/issues/441)). What you may notice:

- A window starts without building the tool windows it doesn't show, each built as you first open it; together they took about 600 ms of a two-second start.
- A warm reopen reads its cached project builds in parallel.
- A key costs what it changed, not the file's size: while a solution loads, in a long run of `//` comments, among inlay hints, with soft wrap and folds, with the find bar open, in a file being debugged, and with thousands of warnings.
- Completion narrows its list off the window's thread and keeps its rows; Go to File keeps only the best matches as it scores.
- Git and the other programs Passenger starts, the language server's long answers and a folder's saved state as it opens are all handled off the window's thread.
- An agent's calls cost your window what they ask, not the size of the files they name.
- An AppHost's services start at once, one service's restart reads only its own console again, and following logs and traces costs each record what it adds.

## Fixes worth knowing

- Files holding a lone carriage return or a Unicode line separator (U+0085, U+2028, U+2029) no longer send Go to Declaration, breakpoints, build errors, console links or stack frames lines away from where they belong.
- Find in Files, Replace in Files and Find Usages read UTF-16 files, and Replace in Files goes on past a read-only file, saying which it couldn't change.
- An open file whose folder is moved or renamed outside Passenger follows it, and one whose folder is deleted is never saved back there. After the system drops folder changes, as a large checkout makes it do, open files and the Explorer catch up.
- Renaming a project renames its solution entry and every reference to it, and moving a file keeps the project's Remove and Exclude naming it.
- A save on Windows keeps the file's attributes, its permissions and its alternate data streams.
- Move Line, Delete Line and Duplicate take a folded method whole.
- A git hook that leaves a job running no longer holds a commit for good, and a conflict where one side deleted the file is kept or deleted whole, never saved empty.
- A login shell that leaves a background job no longer delays every git and dotnet start by 10 seconds.
- A NuGet feed's credentials go only to its own host, and an advisory's link opens only a web page.
- Prettier gives each file only its own text, Prettier 2 works beside a `.prettierignore`, and Save saves the file it was pressed on.
- A build typed in the terminal no longer deletes what Passenger's own build wrote, which had left a program unable to start ([#413](https://github.com/Zaneris/passenger/issues/413)).
- Exit, or Restart to Update, with unsaved changes to a read-only file goes on once you answer.

## What you may notice changed

- **The keypad's keys are keys of their own.** A shortcut recorded on the numeric keypad's / stays the keypad's, shown as NumPad / (⌨/ on macOS), where it became the main /. The Visual Studio keymap binds the keypad too: Ctrl+NumPad / (⌘⌨/) comments a line and Ctrl+NumPad - (⌘⌨-) goes back ([#445](https://github.com/Zaneris/passenger/issues/445)).
- **Debug or Run of a configuration that's running** stops it and starts it again, where it said "Already running"; that is now said only of another program in the Run console, by name. A configuration that runs shows "(running)" after its name in the toolbar.
- **File > Open** opens any file, not only a solution, project or folder; a binary file with no view of its own opens read-only as its bytes, and a file over 64 MB is refused, saying why.
- **The Solution view's keys follow your keymap:** Rename is Ctrl+R, R (⌘R, R on macOS) in the Visual Studio keymap and F2 in VS Code's, where F2 renamed a row whatever the keymap.
- **Container launch profiles run:** `Docker`, `DockerCompose` and `SdkContainer` profiles, greyed in 0.1.0, run in containers.
- **Every file has its own icon,** where most files shared a few.
- **WPF's preview runs your code in design mode,** so code that checks for a designer takes the designer's path there.
- **Agents' tools** were folded and renamed, and an agent asks before running code in your program or setting breakpoints (both above).

## Known limits

- **Windows containers aren't supported.** Switch Docker Desktop to Linux containers; while it runs Windows containers, the status bar says so.
- **Podman** works both ways it is set up: Docker's command and Compose v2 on Podman's socket, or Podman alone with `podman compose` running Docker's Compose v2 (not the Python `podman-compose`). Podman has no BuildKit, so Dockerfiles go unchecked there, which Passenger says once; and removing a container that ignores SIGTERM takes Podman's 10 seconds. Not handled yet: SELinux's relabelling of bind mounts (Fedora, RHEL) and rootless Docker. On Ubuntu 26.04 the pasta AppArmor profile refuses Podman's signal, so removing a container can fail until Ubuntu fixes it; a `signal (receive) peer=podman` rule in `/etc/apparmor.d/usr.bin.pasta` lets it through.
- **Debugging or profiling in a container** downloads Passenger's container tools for its system (Linux x64 or Arm64, glibc or musl) from this release the first time, checked against the release's checksums. A container started with `DOTNET_EnableDiagnostics=0` can't be debugged or profiled, a Release build has none of its code stop under Just My Code, and an image of another processor runs emulated; each is said as you start.
- **A compose app's logs and traces** are read from the dashboard on the engine's machine, so with a remote engine the run says it can't reach them.
- **Aspire** needs 13.6 or a later 13.x. A service that is a single `.cs` file isn't run by Passenger, though a single-file AppHost is.
- **The Requests window** reads ASP.NET Core's and EF Core's events, and a command's values show only where the app logs them (EF Core's sensitive data logging), else as `?`.
- **Pending model changes** need EF Core 8 or later.
- **Publish** goes to a folder; a profile that deploys elsewhere (Web Deploy, FTP, Azure) is listed but not yet used.

## Updating

Installed copies on macOS and Windows offer a new version in the status bar, and Restart to Update installs it. On Linux, unpack the new archive and run its `install.sh` as before. Your settings are kept.
